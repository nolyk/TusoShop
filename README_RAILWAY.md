# AutoShop: Railway

Загружайте в GitHub содержимое этой папки, не родительский проект с `.env`.
Docker запускает `python run.py`: схема PostgreSQL → Mini App + бот.
Сервис слушает `0.0.0.0:$PORT`. `/health` проверяет соединение с PostgreSQL.
Один сервис, одна реплика, без ngrok, start.bat и отдельного веб-сервиса.

## Первый запуск

### Если сейчас падает Migrate volumes

Ошибка `parked in BUILDING` относится к состоянию deployment в Railway,
а не к Python. В сервисе, указанном в ошибке, отмените зависший deployment
`7c647d49-5039-4414-b2d2-b2d891395899` (Cancel) или дождитесь его завершения,
затем повторите неудачный deployment. Не удаляйте volume
`a998e843-e39d-43ec-afa8-4bb730056d02`: на нём могут быть данные PostgreSQL.
Если отмена недоступна или состояние не меняется, передайте эти два ID поддержке Railway.
Новый Dockerfile сам по себе не снимает эту блокировку.

### Какую папку разворачивать

В исходном проекте Railway-файлы находятся в `delivery/railway/railway-ready`.
Если подключаете весь исходный репозиторий, задайте эту папку как Root Directory
сервиса AutoShop. Если загружаете содержимое `MODIFIED_FILE.zip` в отдельный
репозиторий, оставьте Root Directory `/`. В выбранном корне должны лежать
`Dockerfile`, `railway.toml`, `run.py`, `requirements.txt` и `tgbot`.
Уберите старые переопределения запуска `python main.py` / `python web_main.py`:
Start Command должен быть `python run.py`, Healthcheck Path — `/health`.
Не переносите инициализацию БД в pre-deploy; она выполняется при запуске.

1. Загрузите содержимое папки в репозиторий GitHub.
2. Railway → New Project → Deploy from GitHub Repo → выберите репозиторий.
3. В том же Railway-проекте добавьте PostgreSQL.
4. В Variables **сервиса AutoShop**, не PostgreSQL, добавьте:
   - `BOT_TOKEN` — токен BotFather.
   - `BOT_ADMINS` — ваш числовой Telegram ID; несколько ID через запятую.
   - `DATABASE_URL=${{Postgres.DATABASE_URL}}` — ссылка на переменную сервиса базы.
     Если сервис базы переименован, используйте его имя вместо `Postgres`.
5. В Settings → Networking нажмите Generate Domain. Адрес Mini App возьмётся
   из `RAILWAY_PUBLIC_DOMAIN`. Для своего домена задайте `WEBAPP_URL=https://...`.
   После настройки переменных/домена выполните Deploy/Redeploy.
6. Остановите локальную копию бота с тем же токеном. Откройте бот → `/start`.
   Кнопка меню Mini App устанавливается автоматически через Telegram Bot API.

Бот и web-приложение используют одну PostgreSQL. Локальная `database.db` не является
источником данных этого приложения. Старый каталог/балансы нужно перенести из вашей
существующей PostgreSQL отдельно, если они нужны; этот пакет не содержит клиентских данных.
На чистой базе создаются таблицы и начальные настройки. Отключите техработы и включите
покупки/пополнение в админке; добавьте товары и настройте нужные платёжные методы.
По умолчанию существующая логика проекта создаёт `is_work=true`, `is_buy=false`,
`is_refill=false`: до настройки магазин не принимает покупки.

## Где Mini App и админки

- Mini App: публичный HTTPS-домен сервиса и кнопка меню **Mini App** в боте.
- Все существующие админки находятся **в Telegram**, не по адресу `/admin` сайта.
  Откройте личный чат с ботом, отправьте `/start`, затем `/admin`.
  Доступ разрешён только Telegram ID из `BOT_ADMINS`.
- В меню сохранены настройки, переключатели, пользователи, статистика, товары,
  платежи, рассылки, рекламные кнопки, подписки, баннеры, конкурсы и Stars / Premium.
- На новой базе администратор может войти при включённых техработах;
  включение продаж и пополнения выполняется отдельно через переключатели.
- Старый `WEBAPP_HOST=127.0.0.1` не закроет Railway-сервис: при наличии
  `RAILWAY_ENVIRONMENT_ID` привязка принудительно `0.0.0.0`; порт берётся из `PORT`.

## Переключатель Stars

Админка → Stars / Premium (цифровой магазин) → **⭐ Продажа Stars: вкл / выкл** →
**Включить** или **Выключить**.

Выбор сохраняется в `digital_settings.stars_enabled`, перекрывая начальное значение
`DIGITAL_STARS_ENABLED`. Перезапуск не нужен. При выключении Stars исчезают из нового
каталога/меню, старые кнопки и запросы цены отклоняются, списание баланса блокируется
в транзакции. Уже оплаченные заказы не отменяются. Общий `DIGITAL_SHOP_ENABLED=false`
выключает весь цифровой магазин независимо от переключателя Stars.

Не путайте **продажу Stars** и **пополнение баланса звёздами**: второй переключатель
уже есть в Админка → Платёжные системы → Telegram Stars.

## Что не появляется автоматически

- Настройте платёжные провайдеры в админке и их ключи, прежде чем принимать деньги.
- `MARKETAPP_API_TOKEN` нужен существующему расчёту цены/получателя Stars и Premium.
- Автоматическая выдача Stars/Premium в исходном проекте не подключена к исполнителю.
  Оставляйте режим **Вручную**: администратор выдаёт и закрывает оплаченный заказ.
  Развёртывание в Railway само по себе не подключает провайдера выдачи.
- Если сохраняете кошелёк, задайте постоянный `WALLET_ENCRYPTION_KEY` (Fernet).
  Не меняйте ключ без переноса зашифрованных секретов. `JWT_SECRET` также рекомендуется
  задать постоянным случайным значением.

## Эксплуатация

Railway использует Dockerfile и railway.toml из корня. Новый push в связанную ветку
запускает очередной deployment. Держите одну реплику: FSM в этом проекте в памяти.
Во время rolling deploy PostgreSQL advisory lock не даёт двум новым версиям выполнять
getUpdates одновременно. Web healthcheck может быть готов, пока новый бот ждёт завершения
старого. У старого локального main.py такого lock нет — его обязательно остановить.
При перезапуске незавершённые диалоги выбора сбрасываются, заказы и настройки остаются в БД.
Настройте резервные копии PostgreSQL средствами Railway. Файловый volume приложению не нужен.
